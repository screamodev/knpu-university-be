# Деплой на прод — зміни від 08.08.2026

Самодостатня інструкція: тільки те, що треба зробити після `git pull` у **обох** репозиторіях.
Нічого з попередніх частин `DEPLOY-PROD.md` тут повторювати не потрібно.

Що їде: сторінки 27 кафедр, центр забезпечення якості освіти з дампа (новини + закриті раніше
розділи), студентське самоврядування, 127 наказів, разові вчені ради з редіректами, дерево
категорій новин, пошук по сайту, три розширення адмінки.

**Перед стартом**

```bash
export DIRECTUS_URL=http://knpu-university-directus:8055
export DIRECTUS_TOKEN=…        # статичний токен адміністратора: прогони тривають годинами
```

Адреса саме внутрішня: на проді Directus не слухає `localhost:8055` (порт не опублікований, усе
йде через nginx), а публічний домен веде через Cloudflare, який рве багатогодинні завантаження.
Тому всі python-команди — у контейнері `python:3.12-slim` **з `--network webnet`** (мережа, у якій
живе Directus) і обов'язково з `-e DIRECTUS_URL -e DIRECTUS_TOKEN`: без них скрипт піде на
`http://localhost:8055` всередині контейнера й впаде з `Connection refused`.

Токен береться в адмінці: **Users → свій обліковий запис адміністратора → Token → Generate**,
зберегти й натиснути Save (після збереження значення більше не показується). Замість токена
можна передати `-e DIRECTUS_EMAIL -e DIRECTUS_PASSWORD`, але сесія живе 15 хвилин — для довгих
прогонів не годиться.

Скрипти ідемпотентні: перерваний прогін просто запускається ще раз. Файли `files.map.json` на
проді свої — не копіювати з локальної машини.

## 1. Бекап

```bash
cd knpu-university-be
set -a; . ./.env; set +a          # обов'язково: доступи до БД лежать у .env, а не в оточенні

docker run --rm --network dbnet -e PGPASSWORD="$DB_PASSWORD" -v "$PWD":/backup postgres:16-alpine \
  pg_dump -h "$DB_HOST" -p "${DB_PORT:-5432}" -U "$DB_USER" -d "$DB_DATABASE" \
  -Fc -f /backup/knpu-2026-08-08.dump
docker run --rm -v knpu-university-be_uploads:/uploads -v "$PWD":/backup alpine \
  tar czf /backup/knpu-uploads-2026-08-08.tar.gz -C /uploads .
```

> `pg_dump: connection to server on socket "/var/run/postgresql/…" failed` означає рівно одне:
> `$DB_HOST` порожній, бо `.env` не підвантажено — виконайте рядок `set -a; . ./.env; set +a` і
> повторіть. Перевірити: `echo "$DB_HOST $DB_USER $DB_DATABASE"` має показати три значення.
> Якщо натомість буде `server version mismatch`, візьміть образ під версію сервера:
> `docker exec knpu-university-postgres postgres -V` → `postgres:<версія>-alpine`.

Перевірити, що дамп не порожній: `ls -lh knpu-2026-08-08.dump` (мають бути десятки МБ).

## 3. Схема + розширення + права

```bash
cd ../knpu-university-be/migration
docker run --rm --network webnet -e DIRECTUS_URL -e DIRECTUS_TOKEN \
  -v "$(pwd)/schema":/w -w /w python:3.12-slim python apply_schema.py --dry-run
docker run --rm --network webnet -e DIRECTUS_URL -e DIRECTUS_TOKEN \
  -v "$(pwd)/schema":/w -w /w python:3.12-slim python apply_schema.py

cd ..
docker compose -f docker-compose.prod.yml restart directus     # підхопить нові extensions/
docker compose -f docker-compose.prod.yml ps                   # дочекатися healthy (~30 с)
docker compose -f docker-compose.prod.yml exec -e PUBLIC_URL=http://127.0.0.1:8055 directus \
  sh /directus/snapshots/bootstrap-public-access.sh
```

`-e PUBLIC_URL=http://127.0.0.1:8055` обов'язковий: типово скрипт іде за публічною адресою, тобто
через Cloudflare, і на щойно перезапущеному контейнері отримує 502. `127.0.0.1`, не `localhost` —
BusyBox резолвить `localhost` у `::1`, на якому Directus не слухає.

Перезапуск обов'язковий: у `extensions/` приїхали `auto-fill-text`, `cover-hero-focal`,
`text-with-tooltip`. Без `bootstrap-public-access.sh` нові колекції (зокрема `legacy_redirects`)
не читаються публічно — редіректи й нові сторінки будуть порожні.

## 5. Файли всередині текстів (~2 300 PDF, довго)

Контейнеру треба бачити **обидва** репозиторії, тож монтуємо їхню спільну теку (`$HOME`):

```bash

  docker run --rm --network webnet -e DIRECTUS_URL -e DIRECTUS_TOKEN \
    -v "$HOME":/srv -w /srv/knpu-university-be/migration/pass2 python:3.12-slim \
    python mirror_page_files.py "$@"

mirror --content /srv/knpu-university-fe/app/content/pages --unlink-missing
```

## 7. Фронтенд

На дроплеті з 1 ГБ RAM збірка Nitro не влазить у памʼять («Ineffective mark-compacts near heap
limit»), тож спершу своп — один раз на сервер:

```bash
free -h
fallocate -l 4G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab      # щоб пережив перезавантаження
```

```bash
cd ../../knpu-university-fe
docker compose -f docker-compose.prod.yml build app     # білд збирає індекс пошуку
docker compose -f docker-compose.prod.yml up -d app
```

Ліміт купи для збірки задає `NODE_OPTIONS` у `docker/Dockerfile.prod` (типово 3 ГБ). Якщо памʼяті
на сервері стане більше, нічого міняти не треба; якщо збірка все одно падає — підняти своп до 6 ГБ.
